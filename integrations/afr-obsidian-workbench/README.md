# AFR 与 Obsidian 工单交接

研究者在 Autoloop 里安排工作，在 AFR 与 Obsidian 里积累材料。这里补齐同一张工单的接续。从「知识库 › AFR 成果」查看已签发的白板、完整阅读和研究问题，从工单详情进入可固定一份引用。研究报告就绪后，可以将选中轮次保存到 Obsidian，并从新笔记回到原工单、原轮次。

| 操作 | 用户看到的结果 | 数据边界 |
| --- | --- | --- |
| 浏览 AFR 成果 | 按研报或研究问题检索，点开查看主题、证据关系和 Obsidian 入口 | 本机 AFR 仅提供标题、版本和定位 |
| 从工单添加引用 | 先显示目标工单。保存并刷新后，这条固定引用仍可查看 | 交接独立保存，现有授权、自主选材和派发沿用当前工单流程 |
| 保存本轮报告 | 显示所选轮次及写入回执。可在 Obsidian 打开，笔记能回到同单同轮 | 核对工单和已归档轮次，只向「Autoloop 工单交接」新建笔记 |
| 版本变化或目标笔记被手改 | 提示重新选择或核对状态 | 不覆盖手改。相同轮次的重复保存合并为同一交接 |
| 飞书工单 | 继续查看同单进度和待办 | 资料、白板和保存入口在电脑工作台，飞书投递范围沿用原设置 |

用户验收从一张合成研究工单开始。打开 AFR 成果，把已签发材料固定到该工单，刷新验证引用仍在。打开一个已归档轮次，保存到 Obsidian，再通过新笔记留的链接打开同单同轮。复核重复点击、过期版本、跨工单请求与手改保护。交接使用现有工作台与本机 AFR 读取能力，模型授权由原有流程管理。Obsidian 库的同步遵循用户自己的设置。

## 兼容及恢复

本模块面向正在使用的 Odyssey 工作台。其入口含 research.js、research_library.py 和 --afr-config。GitHub 的 V2 候选分支提供另一套独立 AFR 查询页。两套服务器有不同入口，部署前以正式源码和指纹核对。开发基线为 Autoloop 候选 30e2987、AFR c900dd2 和与当时运行副本一致的工作台源码。

apply_local.py 接受 --source（现有应用目录）和 --output（尚未创建的目录），校验接入位置后生成一组可审查的替换文件。运行账本、配置、原件与地图资产无需移入仓库。将生成文件叠加到隔离工作台副本，使用独立端口、账本、中台目录和合成 Vault 验收。

--afr-handoff-config 指向当前用户的私有 JSON，字段为 root（AFR 发行代码目录）、python（兼容运行时）和 vault（Obsidian 库目录）。同一配置也可保存为应用目录的 afr-handoff.local.json，由原启动命令识别。

上线前备份受影响的四个入口与私有配置，核对现役指纹。回退恢复四个入口与原配置，保留工单账本、交接记录和用户编辑过的笔记。
