# 本机任务工作台（发行候选）

同一张工单贯穿网页、本人飞书私聊和 Codex 执行器。此包使用独立文字界面，不需要个人快照、游戏图片、三维素材、Google 账号或 DSH。默认不安装任何程序、不启动飞书、不运行模型。不要将整个个人工作区作为仓库发布。

## 五分钟离线验收

在可创建本机回环监听、可运行 Python 3.9+ 的 macOS 环境，解压后运行：

```sh
python3 -B verify_demo.py
```

它复制白名单运行代码到临时位置，设置全新 HOME，实际启动看板两次，向本机接口提交一张样例工单，验证重启后工单未丢失且故障仍然如实显示。不连接模型或飞书，不写正式配置；未安装中台时，应显示「已保存，未派发」，不能显示已完成。手动查看：从解压目录运行 `python3 -B server.py --port 8765`，在该电脑打开 `http://127.0.0.1:8765/`。Ctrl+C 停止；任务在该目录的 .runtime，勿提交或随包复制。当前未验证 Windows。

## 接通自己的执行器

1. 单独配置 [Agent Autoloop](https://github.com/KKKKhazix/agent-autoloop) 的本机中台和 worker；本包不包含它，也不复制其密钥。核对过的上游提交为 e8748fd，依赖 Node 24+、MIT。应用需要其 `~/.agent-autoloop` 标准配置、local 来源和本人卡片接口。
2. 安装并用自己的账户登录 Codex CLI，先验证账户可用模型与目录 `agent_catalog.py` 一致。worker 的 PATH 需能找到 codex，或由操作者在其环境显式设置 `ODYSSEY_CODEX` 绝对路径。要求 CLI 支持 `exec --ephemeral --json --output-schema --output-last-message`、只读/工作区写入沙箱以及本版本使用的其他参数。没有个人 Skill 时会使用包内角色指南。不包含模型、订阅或调用额度。默认发行页走全 Codex；不能从网页提交程序路径或凭据。
3. 用相同 Python 和最终解压路径运行 `python3 -B configure_workbench.py` 生成并验证候选；检查范围后才用 `--apply` 首次登记专用规则、通道和 worker 命令。脚本拒绝覆盖不同的已有规则；移动目录需重新核对登记。停止看板不能代替停止已在中台领取的任务。
4. 在看板新建无敏感资料的任务，确认方案后检查真实产物和独立审核记录。执行器需要可信宿主的进程检查权限。

要用合成样例验收两类任务，在全新解压目录中、首次启动看板或生成中台候选配置之前运行 `python3 -B smoke_case.py prepare .runtime 全部`。同一看板会出现「隔离验收：代码修复」和「隔离验收：资料报告」，各有独立工作区和 15 分钟预算。命令只预置资料并登记工单。按上面步骤接通与这份安装匹配的 worker 后，可在各单点「开始或继续」，按当前方案完成审批。独立验证时对照包内固定测试复核代码样例，在隔离副本运行原测试；对报告执行 `python3 -B smoke_case.py check-report 工单输出目录` 检查 JSON、报告表格逐行数值和来源。另核对工单中的真实角色调用与复核证据。

**不改源码选择账户可用模型：** 在包内私有运行目录 `.runtime/codex-models.json` 配置别名，例如 `{"gpt-6-astra":"YOUR-ACCOUNT-MODEL"}`（把右侧替换成自己实际验证可用的模型 ID，不是凭据）。不配置就使用原目录的 ID。新任务在第一次调用前固定实际模型；修改映射不能让已固定的旧工单静默换模型。请勿提交此文件。

## 可选：本人飞书

在机器人私聊直接发送需求，点击「新建工单」或「补充已有工单」选择归属。任务卡上可点击「我的工单」按标题选单，也可查看进度、补充资料或查看当前方案。开始、暂停和批准方案须在对应的确认卡上操作。原文字及斜杠入口兼容已有用法。

按钮依赖飞书已发布的 `card.action.trigger` 回调。本机 CLI 的 `event status --current --json` 可查看现有监听。若该事件已由同一机器人的 Autoloop 飞书通道接收，将桥配置 `shared_clicks` 设为 true，把 `shared_clicks.py`、`bridge.py`、`click_cards.py` 和私有 `settings.json` 放在同一目录，给共享入口脚本执行权限。桥配置的 `lark` 指向真实 CLI 的绝对路径，Autoloop 的飞书通道配置 `lark` 指向 `shared_clicks.py`。备份后重启对应服务，并核对事件总线只有一个卡片消费者。共享入口保留原通道的事件流。独立部署可由桥直接监听。

需自行配置授权的飞书机器人和 lark-cli，确保其可读取该本人私聊、可用 bot 身份发消息；CLI 与平台各自适用其许可证/服务条款，不随本包分发。复制 feishu.example.json 到不纳入版本控制的私有配置，填写本人 open_id、同一台电脑上的绝对路径；不要用共享账户或公用目录。创建一个只属于自己的 0700 目录，作为 Unix socket 的父目录。

看板加 `--feishu-socket /绝对/私有目录/board.sock`，另起 `python3 -B feishu/bridge.py --config /私有目录/feishu.local.json serve`。先只验接单：本人发「新任务：目标」，回复返回的卡补充。手机不打开 localhost。要启用手机决策，另用私有 0600 文件保存随机 32 字节，将该文件路径同时显式配置给看板 `--feishu-decision-key` 和桥配置 `workbench_decision_key`。只接单的部署不要设置这项。不得共享运行密钥或转发原始产物。

## 发行与回退

飞书提醒按工单选择：回复已送达的本人任务卡「订阅提醒」或「关闭提醒」。普通排队、执行心跳、修改投递次数不会发进度消息，也不会通过通知启动第二次执行。看板离线或无法核实状态时不报完成。提醒不包含原件、阻塞原始日志或执行命令。

- 本包脚本仅用 Python 标准库；网页只含本项目文字、HTML、CSS 和 JS，无 CDN、字体、游戏美术或第三方浏览器包。可用 `shasum -a 256 -c SHA256SUMS` 检查导出后是否被改写。清单不是来源签名。
- 本仓库代码的发布许可需由权利人决定；未选许可证不代表允许任意再分发。不要误用上游 Autoloop 的 MIT 为本项目授权。
- 发布前要以独立账户复验，确认许可证、平台权限和费用；不得提交数据库、个人配置、认证文件和历史证据。本包未推送 GitHub。
- 回退先停止已确认属于本次部署的看板与桥，不停止无关服务；保留私有库并备份，再使用上次验证过的程序和匹配配置。不要直接用旧整库覆盖运行期间产生的新工单。
