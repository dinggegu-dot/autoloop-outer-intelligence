# 工作台与飞书的产品设计准则

维护对象是使用中的桌面工作台、本人飞书单聊和两端共用的工单。需求评审、实现和验收都从本文开始。调整交互约定时，同一轮更新本文件、对应的界面和验证记录。当前阶段与既有授权见[双端 PRD](PRD-Superagent双端V1.md)。

## 把操作放到用户需要它的位置

| 用户想做什么 | 桌面工作台 | 飞书私聊 | 谁决定是否可做 |
| --- | --- | --- | --- |
| 发起工作、找回一单 | 首页「新建工单」和工单队列 | 工作台导航卡的「新建工单」「我的工单」；选单尽量用可披露的标题 | 新建时输入需求，选择已有工单时点击。对标题相近的单显示短编号 |
| 想知道做到哪一步 | 工单详情首屏给出状态、下一步与进度；可展开时间线 | 工单卡固定「看进度」，普通私聊输入同名查询时先选单 | 只读查询。不得写补充、批准、派工或订阅 |
| 提供资料 | 详情固定「补充资料」，列明本单来源和既有补充 | 本单表单、原卡回复均绑定工单；提交成功给回执 | 输入框只收真实内容。补充资料保持当前授权，改变范围时另走方案修订 |
| 需要我决定 | 「待我处理」给出原因。方案、预算、改版和阻塞分别处理 | 从本单进入当前可办事项，收到明确的方案或控制卡再作决定 | 后端在提交时核对身份、工单、版本、批准对象和当前状态。两端冲突时展示已生效决定 |
| 看成果、换设备 | 已交付队列；成果页列出版本、产物与验收证据。详情提供跨端接续 | 可查当前工单进度与交付状态，完整文件在电脑查看 | 工单号和版本贯穿设备。原件、工作目录和凭据留在本机 |
| 系统断开或结果未知 | 明示待核对，保留最后已知记录和只读入口 | 可回工作台或重新查询，在证据恢复后再显示可执行决定 | 缺少回执、账本不可用和余额不足各自有明确反馈 |

## 页面骨架

- **桌面首页**回答「有什么需要我处理、系统在做什么、哪里有交付」。队列和新建位置固定。工单首屏回答「哪张单、现在怎样、我能做什么」。角色、步骤图、历史版本、用量和原始证据按需展开。历史地图保留独立入口。
- **飞书首页**只负责发起和找回。长期导航卡可从会话中重复打开。会话中的置顶与机器人输入框的悬浮菜单是两项平台配置，分别验收。普通工单卡固定放查询、补充和导航，能改变任务的决定要显示具体对象与后果。手机过程无需打开本机地址。
- **渐进展示**。主界面先呈现最常做的选择；改版、历史和处理失败分别有去处。能够直接点选的已知选项不得要求复制编号或输入命令。需要创作或提供新信息时，输入框标明提交对象和结果。按钮变多时先归类，再决定是否需要新增页面。
- **同一套语义**。「补充资料」产生笔记；「修改本版要求」产生修订；「看进度」读取记录；「批准」提交当前版本决定。显示「已登记」「已派发」「已交付」分别要求工单、派工、交付验收的证据。查询按钮本身绝不启动执行。
- **保护上下文**。切单、筛选、刷新和换端都要核对工单。收件、派工、执行会话和成果各有编号。迟到回执可追溯，订阅提醒本身不产生授权。未明确目标的暂停先选工单，AFR 仅在明确指定时可操作。

## 给每个新功能配一份呈现设计

开发前写明使用者的意图、它归属于全局还是单张工单、出现和消失的条件、可见数据、用户需要输入什么、后端动作和证据。分别画出电脑和手机的入口路径，以及中途换端后的落点。若某端暂时做不到，说明该端可以完成到哪一步，以及如何安全地在另一端继续。

例如引入「按哪个日期分组」时，可以把两个真实字段作为选项，只在当前工单确实缺少日期口径时出现。点选后两端都能看到采用的字段和版本，旧问题重复提交不得改写已生效选择。它应写入澄清记录，不能伪装成用户已经批准执行。该例是后续结构化澄清功能的验收要求。

验收至少覆盖一次正常操作，以及与这项能力有关的反例。常见反例包括两单同开、手机旧卡、空队列、连接中断、重复点击、只读查询误写入。浏览器检查首屏、焦点、长标题和窄屏；卡片检查真正可点的动作、实际回执以及手机是否仍须键入命令。分别记录代码测试、实际服务和本人设备验证。配套用法见[开发指令与验证材料](双端开发指令与验证材料.md)。

### 目标工单的动作与证据

- 在电脑选择目标工单，或从执行详情进入「查看本工单的外层模型调用」。每次尝试单列，按需展开输入快照、可见模型返回、耗时、用量和失败原因。新 Codex 回执同时保存提示词与当次输出 Schema。旧字段缺失时显示「未记录」。打开记录只查询本机账本。

- 本人已点暂停后，等待原轮次退出期间，手机提供「看进度」。只在任务停稳后提供继续入口。暂停卡的工单号、版本、停办代次须在写入停止决定的同一事务中核对。
- 两端用同一状态决定能否暂停及继续。已登记等待系统规划。暂停要区分「已请求，正在停止」与「已经停稳」。继续绑定该次停办，原方案尚未获批时仍回到原审批。暂停和续办在工单中记录实际渠道。
- 阻塞或预算用完时，详情指向已有检查与失败原因。菜单仅呈现当前目标路线支持的动作。方案内的自主修复和调整写入执行记录。扩大范围需要新的授权。
- 飞书用于查看结果和处理当前决定。看板的「方案与执行」展示最近一次逐项核验，「调整与记录」展示 Autoloop Run 与决定。交付下载使用绑定最终验收的版本。阶段通过和整体交付分别呈现。
