# 正式工作台的 Codex 团队入口

新版默认入口为 Router 团队工单。原单批准后推进制作，补充消息由工单订阅续接；固定试单和历史版本使用各自的授权记录。[操作与核对方法](../product/router-ticket-teams.md)

正式 `127.0.0.1:8765` 的「新建工单」里，展开「完成标准、名称与执行设置」后，可在提交按钮下方找到「合成试单」。选择「提交合成索引试单」会发送固定模板标识，重复点击回到同一张试单。进入原单后，可以核对目标、验收和预算，批准一次，再查看执行与交付。灰度只使用仓库内置的合成文件名。普通工单、AFR 本机资料和飞书入口继续使用各自现役服务及授权。

Router 版独立运行的 Hub 与执行进程各有两个并发名额。原有 Hub 账本和工单账本在原路径。旧版本单名额配置保留在原处，程序回退后可读取历史记录。回退前请在新版办完或暂停正在推进的 Router 工单；已归档文件仍可回读，等待选方向、渠道授权及按新角色配置续办的事项需恢复相应新版程序后办理。

## 团队审稿的限量升级

已运行索引灰度的本机可在原入口增加「提交合成简报试单」。固定简报会进入原单的第 2 步审稿。可以查看同版初稿、选择列出的方向、查看验收和按批准方式签收。网关只接受内置合成模板和带版本的操作。团队灰度的选择使用固定选项。

## 开放自定义工单

在正式首页点「新建工单」，写下目标，勾选允许发送本单文字，再点「提交工单」。默认交给工单团队处理。需要补充完成标准、指定方案比较方式或切换到普通工单时，展开「完成标准、名称与执行设置」。团队整理好范围后，可在原单核对并批准。工单簿在 `/workbench`。

从原单补充条件、填写自由修改意见或退回作品时，需要确认发送本次文字。结构化选项、签收和追加预算使用各自的确认。追加预算会在确认前显示新总额，续办从已登记的候选开始。团队读取范围限于本单工作区。正式资料外发默认关闭，工作台入口处理用户明确授权的文字。

团队运行进程使用侧服务内的独立运行目录。现有 Codex 登录通过受信启动器接入，个人技能及 MCP 配置保留在个人环境。

上线候选在隔离环境使用 Chrome 从普通入口提交合成工作坊简报。复查演练可用 `scripts/run_authorized_goal_pilot.py` 启动已隔离的工作台源码和现有 Codex 登录。演练只为指定合成工单把初始角色额度设为一轮，以验证追加预算能从已验成果续办。独立机器终验和人工签收各自有记录。[自定义工单实测](../../evidence/goal-team/authorized-workbench-live.json) · [Codex 超时恢复实测](../../evidence/goal-team/codex-review-timeout-recovered.json)

## 升级和回退

工作台流程呈现这一包只涉及程序、样式和回执读取。若需撤回候选代码，针对本次合并提交建立 revert PR。隔离演练将候选源码反向还原至 `45df215`，再用同一份安装基线重新构建，前端和侧服务整包 95 个文件逐字节匹配。实际升级后需要撤回程序时，使用下文的本次升级恢复点，保留期间新增的工单和归档。[界面验收与回退证据](../../evidence/goal-team/workbench-flow-ui.json)

从已合并的干净检出运行下列命令。原始恢复点是安装索引灰度前保存三份原入口和原 LaunchAgent 的目录。安排切换窗口，期间暂停建单、批准及恢复工单，直至主、侧服务通过检查。升级先核对两侧都已排空，再保存现役程序及两侧账本。

```sh
python3 -B scripts/deploy_formal_canary.py --upgrade /路径/原始恢复点 --target-sha 完整提交SHA
```

如需回到升级前版本，使用这次升级新输出的恢复点。回退恢复程序，现役数据库和新产生的工单留在原位置。

```sh
python3 -B scripts/deploy_formal_canary.py --rollback-upgrade /路径/本次升级恢复点
```

回到上一版后，升级期间创建的自定义工单用于查询原单、审计记录和下载已签收成果。在恢复新版前，暂停对这些工单批准、续办或作出方向选择。若有自定义工单必须继续，优先在保留本版文字授权与工作区限制的版本上修复。上一版网关支持内置模板和固定操作，自定义建单、自由意见、退回和追加预算需要新版网关。

回退后如需运行旧固定合成试单，先核对上一版使用的 Codex 登录仍有效。升级恢复点保存程序和账本，Codex 登录由现有运行环境管理。

独立复核在副本执行了程序回退、账本与归档核对。恢复后的旧程序可通过签名处理器读取原单及归档，试验中的 LaunchAgent 停启使用模拟。[隔离回退记录](../../evidence/goal-team/authorized-workbench-rollback.json)

## Antigravity 角色执行器

macOS 实例可安装 Google 官方 Antigravity CLI 到 `~/.local/share/autoloop/antigravity/agy`，使用已登录的 Antigravity 账户。服务端仅接受本机所有者可执行且非组或公共可写的程序。隔离测试可通过服务进程的 `AUTOLOOP_ANTIGRAVITY_EXECUTABLE` 指向已核验的绝对路径。「Agent 小队」按角色选择。登录失效时，从 Antigravity 恢复登录后回原工单重试。

工作台用临时目录启动单轮 CLI，关闭额度购买、个人工具配置和工作区直接访问。模型只获得本轮批准用于处理的文字和实际候选文本，写入角色通过结构化结果交回文件变更。工具请求或输出格式错误会使本轮受阻。正式浏览器新单的接收方确认单独留证，与本单的批准记录一并核对。

## 安装与验证

从已审查的 V2 分支运行 `python3 -B scripts/deploy_formal_canary.py --preflight`。预检读取原工单、研究归档、AFR 目录及固定文章版本，核对 SQLite 和运行中的工单数。旧工作台或 AFR 有工作在执行时，等待它们结束再切换。

用 `python3 -B scripts/deploy_formal_canary.py --install` 安装。安装器先保存并核对三个原入口文件和原 LaunchAgent，随后制作三个账本的 SQLite 备份。新 LaunchAgent 管理独立灰度的 Hub、Worker、调度器和候选工作台。灰度配置、日志、账本和端口在本机持久目录。主、侧工作台之间只通过受签名校验的回环连接。

上线前在隔离副本预检一次。检查正常来源和伪造来源、无有效 CSRF、额外正文、自定义新建和侧服务直连的处理。侧服务不可用时，灰度接口报告暂不可用，原入口继续可读。灰度首单批准前应只有接单研判和验收设计，目标执行的派工数为零。批准一次后沿同一工单下载 `search.py` 与 `update.py`，核对批准记录、独立终验和下载字节。故障注入、Worker 重启和暂停后迟到提案的实测在隔离副本进行。[隔离及恢复记录](goal-coordinator-rollback.md)

## 回退

1. 暂停灰度新操作。有在途工单时从原单暂停，等待 Hub Run 终结、活动派工清空和子进程退出。保留新工作台、Hub、Worker 及产物路径。
2. 从本机 `state/deploy-before` 找到安装器输出的正式恢复点。运行 `python3 -B scripts/deploy_formal_canary.py --rollback /绝对路径/outer-canary-恢复点`，核对备份摘要后恢复原工作台文件和 LaunchAgent。即使切换中途退出，也可用事先写入的恢复清单。原账本及切换后新增记录仍留原处。
3. 回读 8765 的旧工单、工单报告、AFR 目录和飞书桥状态。灰度独立账本保留在原路径。灰度工单排空后可停用 `local.autoloop.workbench-outer-canary`。若要再次开放旧灰度工单，先对账，再为既有侧服务按原路径和端口重新接入同源入口。
