# 一张工单，两层分工

你同时推进几个项目时，首页先列出需要你决定的事。每张单写清为什么停、该点哪里、现在依据哪一版。批准后，模型团队自行传递意见、改产物、复验。你始终回到同一张原单看证据和下载。

本轮在 Autoloop V2 隔离工作台试用，工单通过网页普通新单进入，由 Codex 执行。V2 原 PRD 继续约束执行引擎、状态和权限。

正式普通新单支持显式选择 Codex 团队。只有确认发送填写的名称、目标和验收文字后才登记给 Codex 研判。原工单里的自由修改意见、澄清和退回各自确认发送。执行仍等待已核对的授权，追加额度需要单独确认。

## 先验收一次完整操作

1. 通过新单写下合成情感场景和想要的成果。核对原话、验收、权限、范围和预算后批准一次。
2. 原单呈现三组小样。本人在同一张单选择一个方向，留一句希望保留或调整的意见。
3. 系统用这条意见续办。详情能看到负责人和顾问的摘要、采用的修法、封存文件、检查结果。等待本人时，调度释放这张单占用的执行槽。
4. 独立复验通过后，客观验收工单按批准方式自动交付。含本人验收条件的工单展示当前候选，等待本人签收或附理由退回。
5. 网页原单能回看工单版本、意见和结果。下载的字节与验收归档一致。用户无需在 Agent 之间转述。

## 工作台怎样对应实际流程

普通工单和 Codex 工单共用首页首区「待我决定」。同一张单只占一个位置，单独标明来源、等待原因和下一步。一侧连接中断时，首页保留另一侧已确认的待办，恢复后重新核对。正在推进和已交付的 Codex 工单排在下面。

同时跟几张单时，先回答“现在哪件事需要我，点哪里处理”。打开原单以后，再回答“谁在做、看的是哪一版、这次验了什么”。首页的链接定位到当前问题或交付版本，执行权限仍由服务端核对。

| 系统环节 | 用户在哪里看或操作 | 用什么核对 |
| --- | --- | --- |
| 接单、澄清、批准 | 首页新建工单；需要澄清或批准时，从待决定卡进入原单 | 原话、待答问题、目标与验收版本、预算和授权 |
| 本轮派工 | 原单的「进度」展开派工记录 | 当前步骤、轮次、派工回执；缺少可信回执时显示待核对 |
| 负责人和顾问分别提案 | 在「团队审稿」查看双方原方案和负责人取舍 | 同一次派工中的两份模型摘要，以及已登记的比较理由 |
| 看初稿、本人定方向 | 从待决定卡直接看本版封存稿、顾问挑的问题、可选方向，提交本次选项或意见 | 问题、初稿摘要和本人的答复绑定同一版 |
| 执行者返修、负责人复验 | 原单的「返修与复验」呈现问题、保留项、改动和前后版本 | 已保存新版、负责人实际回看的回执及检查结果 |
| 保留现稿 | 若已选「沿用现稿」，在审稿记录核对只读负责人的检查，再看外层验收 | 只展示本单实际发生的步骤 |
| 跨阶段回归 | 首页区分「协调返工」和「独立核验」；在「决定与记录」展开目标协调调用 | 工单范围内的工具记录、采纳理由、修哪一步、保留文件与摘要、接下来验什么 |
| 多单、暂停、预算不足 | 看首页各单原因和当前可用操作。旧执行需先停稳时原单优先提示暂停 | 队列与原单共用当前状态；预算、外发权限和暂停状态限制可提交的动作 |
| 外层独立核验 | 「成果与验收」展示候选版本、机器检查和本人验收项 | 独立核验读取的封存版本及每项结果 |
| 签收、退回、交付 | 打开待签收版本或从首页进入已交付单，可预览归档正文、切换历史版本和下载 | 签收与退回各绑定当时版本，HTML 正文以静态内容预览，下载保留归档原件 |

原单页头只标出当前环节。回归可能把单子带回执行阶段，历史上做过哪些工作以回执和文件版本为准。盲评按既有锁票规则显示，旧工单保留原有记录。查看角色和模型的会话、原始回执、用量时再展开技术明细。

本次界面复核的真实操作和模拟范围见[脱敏记录](../../evidence/goal-team/workbench-flow-ui.json)。之前实际生成并退回、签收、下载两版简报的记录见[合成工单验收](../../evidence/goal-team/authorized-workbench-live.json)。

## 完整协作的放行条件

- 负责人和顾问各自读取同一份与本步有关的原话、验收项和上版信息。负责人在原单说明采纳与舍弃，再产出可查版本的初稿。
- 顾问以只读会话查看这一版实际文件，留下文件、位置和问题。执行者收到负责人确认的修改清单，完工后由负责人检查同一封存版本，再交外层独立验收。
- 修改清单绑定初稿、所选方向、文件与原文。系统核对候选是否落实改动以及是否保留登记内容。选择沿用现稿时，由一名只读负责人逐份核对封存文件，再交独立验收。有修改时照清单交执行者制作，负责人核对新版。顾问和负责人对实际查看的文件留下与版本匹配的读取记录。
- 对后续阶段确需本人决定的工单，前一阶段先完成验收。原单说明待决定的问题、方案差别和所见版本。有效回答只采用一次，执行槽归还后仍按同一授权继续。已确定的决定不会再次出现。
- 在「等你拍板」打开原工单，点「查看这版初稿」，可以逐个查看顾问审阅的封存文件，对照顾问引用的原文和每个方向会改、会保留的内容，再提交选择。打开、切换或收起预览均不算答复。预览只读取当前问题绑定的版本；题目失效后重新核对原单。验收时逐份比对预览和封存文件，同时确认尚未签收的初稿不能从交付入口下载。
- 从普通新单完成一次上述全过程，对照原单的派工、初稿、顾问意见、本人回答、最终检查与实际下载。延迟回执、旧问题和重送答复单独验收。

## 责任与接口

| 谁负责 | 负责什么 | 工单上留下什么 |
| --- | --- | --- |
| Autoloop 外层 | 接单、验收设计、绑定授权和计划、调度、收回回执、协调跨阶段返工、独立终验和交付 | 原话、验收契约、授权、当前和历史版本、派工、失败证据、决定和下载 |
| 内层负责人 Sol | 接住一个实施或返工派工，按规模决定直接执行、先出方案、找顾问或交执行者。亲验本步结果 | 选用理由、候选文件、要保留的部分、验证办法 |
| 只读顾问 Sol | 独立出方案、挑样稿问题或复查实物。复杂架构和高难评测设计可用只读 Astra | 独立判断和一个能复现的问题 |
| 执行者 Sol | 只在本轮候选工作区完成修改并自测 | 候选版本、已做的测试、遗留风险 |
| 项目本人 | 同单批准、答偏好、退回或签收 | 分别登记的事件、来源和版本 |

外层沿用 Codex CLI。内层使用本机 Codex App Server，每个角色使用与本次派工关联的独立会话、受控输入和具名权限。复杂任务可以咨询，短脚本默认让一名角色完成，外层复用独立验收。角色只建议业务动作，现行工单、暂停状态、范围、授权和预算由引擎在应用动作前重新核对。

## 状态和证据

- 网页首页顺序为等我拍板、正在推进、已交付。待我决定的卡片包含原因和下一步，工单详情优先展示当前候选或结果。
- 普通新单最多同时研判两张。属于同一工单或同一来源会话的事件仍依次处理。一张单在等待你决定时，执行名额可供其他工单使用。
- 批准绑定目标、验收和额度。回复偏好绑定问题版本及候选摘要。签收和退回绑定独立验收过的候选。重送同一请求只返回原结果，过期操作失败且保留证据。
- 负责人检查实际候选时发现明确问题，执行者修改，负责人重新打开新版，确认该问题和保留项。原单展示问题、保留项、改动、前后版本及实测结果。若本次派工剩余时限或调用数不足，先保存原候选与问题。在整单授权还有额度时，续派一次完成修改和复验。整单额度不足时，从原单批准具体增量后再续。新版未改动、保留项丢失或复验失败时，交付保持阻塞。
- 执行者写完返修时先封存新版和待复验记录。若这一刻后 Worker 中断或复验时间用尽，在授权内只续派只读复验。负责人明确拒绝过该版时，早期的待复验记录不会替代拒绝结果。
- 派工回执在一次结算中核对身份、授权、暂停代次、角色会话和实物。Worker 重启时从持久回执恢复同一轮，旧轮、重复回执或缺失关键证据时保留原单记录并阻止错误晋级。
- 新的暂停操作记录原响应，同一个请求重送时返回原响应，即使工单后来已经继续。历史控制记录按原存档兼容读取。封存返修新版后的复验超时可沿原授权再派一次只读负责人。
- 前序阶段被破坏时，外层独立复验确认后才交给目标协调 Agent。协调工具限定本单，只读失败、已验产物、版本和预算，提案说明修哪一步、保留哪些文件、怎么复验。
- 已派出的协调动作在结算时再次核对原单反馈和授权版本。若派工期间收到新反馈，旧结果只留记录与用量，当前工单按最新反馈继续协调。
- 交付文件从归档读取。保存候选清单和摘要，局部返工要求保留已验字节。故障系列保留错版、拒收证据、协调决定和修复版本。
- 盲评使用相同留出输入，单 Sol 和团队各生成同一组例号的回应。受信侧封存两路来源并提供匿名呈现，锁票后才可对照来源、逐条理由、两路模型耗时和人工转述次数。测试操作员输入单独登记。
