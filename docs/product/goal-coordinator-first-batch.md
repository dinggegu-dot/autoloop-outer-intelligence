# 外层 Agent 首批交付

在隔离工作台提交一个软件目标的人，可以从普通新单入口选择目标执行路线，核对系统整理的要求、验收条件和预算，然后批准一次。如果后段实现破坏了前段已经验过的功能，工单应保留有效成果，在同一次授权内完成返工，并把复验结果和交付版次送回原工单。验收者使用合成文件提交文件名索引需求，先使用查询与增量更新功能，再从原工单核对故障、续办和交付。

## 范围与取舍

- 保留现有 V2 的接单研判、验收设计、Hub 派工和 Worker 回执。三个角色使用 Codex CLI。目标协调使用一轮只读会话，Codex 自行调用该轮的工单工具。
- 协调工具只返回本次派工的失败记录、已验产物、计划版本和预算。服务端在读取时核对仍有效的派工。模型建议列出需要修复的步骤、保留的产物版本和复验项。引擎对照当前工单验证后，在同一事务记录决定与待派工。
- 隔离副本使用现行 8765 的入口和合成材料，运行独立的本机服务、数据库和工作目录。历史工单继续沿原路线回读。

## 验收

1. 通过普通入口提交合成索引需求。验证新建索引、按文件名查询，以及更新后旧文件和新增文件的查询结果。
2. 在测试 Worker 上注入一次跨阶段回归。确认错误候选被拒收，协调器通过 Codex 工具读取本单取证，派工在原授权和预算内发生。执行中重启一次测试 Worker，核对恢复依据和派工账本。
3. 原样重送同一回执，验证没有产生重复派工。另在协调返回前暂停，验证仍在途的旧提案不能接续。
4. 从原工单核对调用、理由、派工、保留版本与终验。独立复核者复查真实运行证据及回退操作。
